description: Factory icon IDs are stored in plans we can never migrate — regenerate the registry after a game data change, and never rename an ID

A factory's `icon` is a bare ID (`iron-ingot`, `smelter`, `sq-blue`) resolved through
`web/src/data/factory-icons.json`, which is generated by `web/scripts/generate-factory-icons.mjs`
and committed. Nothing about *how* an icon is drawn is stored on the factory.

**Why:** once an icon is in a plan it is in `localStorage`, in the database and in share links —
none of which we can migrate. Storing the asset path or the game data key would freeze today's
rendering scheme into user data permanently; storing an ID we own means the artwork, label,
grouping and even the emoji character behind an ID can change in one file, and every existing plan
follows. The corollary is the rule: **add IDs freely, never rename or remove one.** A retired ID
does not error — the factory silently falls back to the default glyph, which is the failure mode
this design exists to avoid.

**How to apply:** re-run the generator whenever the game data is regenerated, alongside the
`dataVersion` bump in [[game-data-version-cache]] — new items do not appear in the picker until you
do, and the script refuses to write on a duplicate ID or a missing asset. It builds the catalogue
from the *asset directory* rather than from game data on purpose: filenames come from an item's
display name, so a game data entry whose artwork was never shipped would otherwise render as a
broken image (this is real — the FICSMAS Gift is not flagged `isFicsmas` and slips every other
filter). `factory-icons.spec.ts` asserts every entry resolves to a file that exists, so a bad
entry fails the suite instead of reaching the picker.

Buildings and everything game data has no entry for (miners, belts, splitters, pipes, power
infrastructure, stations, vehicles, equipment) are hand-listed in the script rather than swept up
from the asset folder — so their IDs read like their names (`smelter`, not `smeltermk1`), and
because that folder also holds ~110 alternate-recipe icons that reuse the art of the item they
make, ~430 foundation/wall/ramp variants, and milestone and cosmetic icons, all of which would
bury the useful ones in near-identical tiles.
`FactoryIconDisplay.vue` wraps each variant in its own element for the reason in
[[fontawesome-dynamic-icons]].
