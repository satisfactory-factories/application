The one Prometheus server behind every Grafana dashboard here also scrapes the PS2Alerts and
Albion Roads targets, so anything done to it affects those projects too. It is an LXC on
Proxmox with a small root volume that can be grown trivially.

- **Retention is one global TSDB setting, 180d since 2026-10-02** (`--storage.tsdb.retention.time`
  in the systemd unit). Prometheus cannot set it per target, job or metric; per-SF retention
  would need a second Prometheus or a store with per-tenant retention. Size is unbounded
  (`retention.size` is 0). 90 days of data was 895 MB, so 180d should be about 1.8 GB.
- **Raising retention deletes nothing, and data past the old limit was never pruned.**
- **Config changes need `systemctl reload prometheus`** (the unit's ExecReload sends SIGHUP). A
  restart is only needed for flag changes. The admin API is deliberately off and nothing needs it.
- **Trap: the unit file once had a missing `\` after the retention flag**, so systemd silently
  dropped every flag below it (listen address, admin API, experimental functions). Fixed on
  2026-10-02. After any edit to the unit, compare `/proc/<pid>/cmdline` with what the file says.
- **Host metrics come from Debian's `prometheus-node-exporter`**, bound to localhost, scraped by
  job `prometheus-node`. It is the single largest ingest source (about a quarter).
- **Ingest of about 650 samples/s is normal** and a tiny load. Do not trim it for performance.
  The process writes about 4 KB/s to disk, almost all WAL.
- **The `node_disk_*` metrics inside the LXC show the whole Proxmox host**, not the container.
  For the container's own I/O, sample `/proc/<pid>/io` over a window.
- **Disk alerting belongs to Zabbix**, so there is deliberately no Grafana disk alert.
- **Dashboard "Prometheus - Server Health"** (uid `prometheus-server-health`) is generated by
  `docs/grafana/prometheus.py`. Apply it as in [[grafana-dashboard-via-api]], except it is the
  schema-v1 `POST /api/dashboards/db` with `overwrite`, not the v2 PUT.
- **Editing a remote file over ssh:** a multi-line `sed -i "Na\..."` inside ssh quoting collapses
  to one line and silently comments the insert out. Use a `python3 - <<"PY"` heredoc on stdin.
