# `web` — the planner frontend

The Vue 3 + Vuetify 4 single-page app that players actually use. This is the planner UI and the calculation engine behind it; most work on the project happens here.

Prerequisites (Node, pnpm) and the one-time workspace install are covered in the [root README](../README.md#local-development). There is no separate install step for this package — a `pnpm install` at the repository root covers it.

## Running

```sh
cd web
pnpm dev
```

Or `pnpm dev:web` from the repository root. Either way the dev server comes up on http://localhost:3000. You may need to load it twice.

The backend is **not** required to work on the planner. Without it you lose login and plan syncing; everything else works off `localStorage`.

## Testing

```sh
pnpm test
```

Vitest, run with coverage. Tests must pass for PRs to be accepted — note that as of writing coverage isn't 100%.

To run a single file or pattern while iterating:

```sh
pnpm exec vitest run factory-management/products
```

Drop the `run` for watch mode.

Most specs live next to the code they cover (`src/utils/factory-management/*.spec.ts`). Broader behavioural suites live under `testing/tdd/`, and `testing/global-setup.ts` stands up a tiny HTTP server that serves the game data file to the suite.

> That test server listens on **3001**, the same port as the API, and *silently skips startup* if the port is already taken. Running the tests while the backend is up therefore makes the suite fetch game data from the API, get a 404, and fail confusingly. Stop the backend first, or start it elsewhere with `PORT=3011 pnpm dev:backend`. See the [port allocation note](../README.md#ports) in the root README.

## Building

```sh
pnpm build
```

This runs `vue-tsc --noEmit` **before** Vite, so a type error fails the build even when every test passes.

## Configuration

`src/config/config.ts` holds the two values that vary by environment:

- `apiUrl` — selected from `VITE_ENV`. The `dev` script sets `VITE_ENV=dev`, which points the app at `http://localhost:3001`; anything else points at production.
- `dataVersion` — which `public/gameData_v<version>.json` the client downloads. Bumping it forces clients to re-download on their next refresh.

Game data itself is generated by the [`parsing`](../parsing/README.md) package — see that README for the regeneration and version-bump workflow, since the two steps have to be done together.
